# json-ui-react


TSX로 쓴 서버 폼 화면을 **정적 JSON UI**와 **행동팩용 서버 모듈**로 컴파일한다. 화면은 `<Screen>`, `<ButtonList>`, `<Tabs>` 같은 고수준 컴포넌트로 쓰고, 서버에서는 생성된 `openScreen(player, id, data)` 한 줄로 연다. 런타임 의존은 0이고, 같은 입력이면 바이트가 같은 출력이 나온다.

```tsx
import { Screen, ButtonList } from "json-ui-react";

export default (
  <Screen id="router" title="Router: screen picked by title prefix">
    <ButtonList name="buttons" count={4} />
  </Screen>
);
```

```js
import { openScreen } from "./generated/screens.js";

openScreen(player, "router", {
  buttons: [["Apple", "textures/items/apple"], ["Bread", "textures/items/bread"]],
}).then((hit) => {
  // null(취소) | { name: "buttons", index: 0..3 }
});
```

## 왜 빌드 시점 컴파일인가

배드락 JSON UI에는 JS 런타임이 없어서 화면 구조가 리소스팩에 정적으로 박힌다. 라우터, 라디오 탭, 고정 `collection_index` 칸, 버튼 번호 배치(`102 + 20k + 19`)를 손으로 맞추면 JSON과 서버 코드가 어긋나기 쉽다. 빌드 시점에 둘을 한 번에 만들면 어긋날 수 없다.

## 파이프라인

| 단계 | 하는 일 |
| --- | --- |
| TSX 화면 | `<Screen>`과 고수준 컴포넌트로 화면을 쓴다 |
| `buildScreens` | 화면들을 한 팩으로 묶는다: 테마, 단일 라우터, `server_form` 훅, 생성 서버 모듈 |
| 저수준 층 | 자체 JSX 런타임, `render`, `createPack`, `createSlots`가 JSON UI 컨트롤로 낮춘다 |
| Lint | 생성된 JSON을 규칙 ID가 붙은 진단으로 검사한다 |
| 행동팩 | 생성 모듈의 `openScreen`이 버튼 순서를 맞춰 폼을 보내고 응답을 `{ name, index }`로 푼다 |

고수준으로 안 되는 배치는 저수준 API로 직접 만들 수 있다. [연구 화면](components/research)이 그 예이고, [API 레퍼런스](api#low)에 저수준 API를 정리했다.
