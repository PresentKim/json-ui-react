# 연구 화면 (방식 E)

연구 화면: 탭 2개, 항목 96개, 상세 96개(방식 E)

고수준 부품만으로 조립한 가장 큰 예제다. 탭 2개(연구 필요, 연구 완료), 탭마다 6x8 칸 격자와 페이지 버튼, 칸마다 미리 만들어 둔 상세를 합쳐 버튼 2022개(칸 96, 탭 2, 페이지 4, 상세 96 x 20)를 만든다. 화면 코드에는 버튼 번호도 `slots`도 나오지 않고, 서버는 `openScreen` 한 번으로 연다.

## 화면 구성

| 부분 | 부품 | 하는 일 |
| --- | --- | --- |
| 탭 | `<Tabs mode="follow">` + `<Tab>` | 위쪽 탭 줄. 탭마다 칸 격자와 페이지 버튼이 따로 있다 |
| 칸 격자 | `<SelectGrid name rows cols detail>` | 칸 하나가 레코드 하나. 칸을 고르면 그 칸의 상세가 오른쪽 판에 뜬다 |
| 페이지 | `<Pager name>` | 왼쪽 판 맨 아래 줄의 이전·다음 화살표 |
| 안내 | `<Placeholder text>` | 칸을 고르기 전 오른쪽 판의 안내 글자 |
| 상세 | `<DetailPanel>` 안에 `IconTitle`, `TextBlock`, `IconRow`, `Spacer`, `ActionButton` | 오른쪽 판의 상세. 아래 `ItemDetail`이 쌓는다 |

화면은 `layout="split"`이다. 왼쪽 판에 탭과 격자, 오른쪽 판에 상세가 놓인다.

### ItemDetail: 사용자 정의 컴포넌트

`ItemDetail`은 인자 없는 함수이고 `<DetailPanel>` 하나를 돌려준다. 자기 상세 화면도 같은 방법으로 만든다.

1. 바깥을 `<DetailPanel footer={...}>`로 감싼다. 자식은 위에서 아래로 쌓이는 스크롤 본문이고, `footer`는 본문 아래에 고정된다.
2. 본문에 작은 부품을 쌓는다. 부품 하나가 레코드의 필드 하나 이상을 이름으로 가리킨다. `<IconTitle name="name" subtitle="status" />`는 레코드의 `name`, `status`, `icon`을 쓰고, `<TextBlock name="desc" />`는 `desc`를 쓴다.
3. 부품 사이 간격은 `<Spacer h={...} />`로 둔다.
4. 아래 고정 버튼은 `<ActionButton name="action" />`이고, 누르면 응답이 `{ name: 격자, index: 칸, field: "action" }`으로 온다.
5. 상세는 `<SelectGrid detail={<ItemDetail />}>`에 넘긴다. 격자가 칸마다 이 요소를 한 번씩 렌더한다.

부품의 `name`은 같은 상세 안에서 겹치면 안 된다(필드 이름이 겹치면 빌드 오류). 레코드 키와 이름이 같다는 점이 중요하다. `IconRow name="mats"`는 레코드의 `mats` 배열을 칸 `count`개(여기서는 8개)로 펼친다.

## 서버 데이터

`<SelectGrid name="needed">`의 데이터는 레코드 배열이다. 칸 하나가 레코드 하나이고, 레코드 키는 상세 부품이 쓰는 이름과 같다.

```js
// 레코드 하나(칸 하나)
{
  icon: "textures/items/book_normal",          // 칸 아이콘이자 IconTitle의 아이콘
  name: "§cItem 1",                            // IconTitle name
  status: "§cNeeds research",                  // IconTitle subtitle
  desc: "Description of Item 1. ...",          // TextBlock desc
  mats: [["textures/items/coal", 3]],          // IconRow mats: [아이콘, 개수]
  rewards: ["textures/items/apple"],           // IconRow rewards: 아이콘만(숫자 자리에 badge "+1")
  action: "Start research",                    // ActionButton action
}
```

탭 글자와 아이콘은 `tabs` 배열이다. 페이지 버튼은 글자가 보이지 않아 데이터가 없다.

## 서버에서 열기

서버는 레코드를 만들어 `openScreen`에 넘기고, 페이지를 넘기면 데이터를 바꿔 같은 화면을 다시 연다.

<Source data={serverSource} />

응답은 `{ name, index, field? }`이다. 칸을 누르면 `{ name: "needed", index: 5 }`, 상세의 버튼이면 `field`가 따라온다(`ActionButton`의 `field`는 부품 `name`인 `"action"`). 페이지 버튼은 `{ name: "neededPages", index: 0 }`(이전) 또는 `index: 1`(다음)이다.

```js
import { decode } from "./generated/screens.js";

decode("research", 102 + 20 * 3 + 19); // { name: "needed", index: 3, field: "action" }
decode("research", 99);                // { name: "neededPages", index: 1 }
```

생성 모듈의 `LAYOUTS["research"]`는 번호가 어떻게 나뉘었는지 보여 준다(길어서 앞부분만 보인다). 칸, 탭, 페이지 버튼이 먼저이고 상세 블록(칸마다 20개)이 뒤에 온다.

## 칸마다 상세를 미리 만든다 (방식 E)

연구 화면의 핵심은 상세 96개를 **서버를 거치지 않고** 바꾸는 것이다. 칸을 고를 때마다 서버에 응답을 보내면 폼이 닫힌다. 그래서 상세를 칸마다 한 벌씩 미리 만들어 두고, 고른 칸의 것만 보인다.

- 칸은 라디오 토글이다. 두 격자의 칸 96개가 하나의 `toggle_name`을 나눠 한 번에 하나만 켜진다(INP-12, INP-35).
- 켠 칸의 `checked` 얼굴 안에 그 칸의 상세 정의가 들어 있다(INP-36). 켜면 상세가 그려지고, 다른 칸을 켜면 이 얼굴이 꺼지며 상세도 사라진다.
- 상세의 위치는 칸 위치만큼 되돌려 오른쪽 판 자리에 맞춘다.
- 칸은 `collection_name`을 가진 가로 `stack_panel`의 직속 자식이어야 고정 `collection_index`가 먹는다(COL-38, COL-50).
- 상세 안의 글자·아이콘은 모두 버튼의 데이터다. 누를 수 없는 칸도 `button()`으로 보낸다(COL-19). 본문은 `common.scrolling_panel`을 재사용한다(LAY-02, LAY-04).
- 번호는 종류 순서다. 칸 격자, 버튼(탭·페이지), 상세 블록 순으로 받으므로 `buildScreens`는 화면을 두 번 낮춘다(첫 번째는 번호 순서를 정하는 데만 쓰고 버린다).

## 출력 동치 테스트

이 화면은 원래 저수준 API로 한 줄씩 쓴 FFR 원본의 재현이었다. 고수준으로 옮기면서 출력이 달라지지 않았음을 세 단계로 확인한다.

1. **FFR 원본**: 서버가 쓰는 원래 UI 정의(`faces.json`)와 버튼 번호 배치(`102 + 20k + 19`).
2. **저수준 재현**: 그 정의를 `createSlots`, `createPack`으로 그대로 옮긴 화면(`tests/helpers/legacy-research.ts`).
3. **고수준 조립**: 위 `research.tsx`.

테스트(`tests/regression/research-high.test.tsx`)는 둘의 **펼친 트리**를 비교한다. 라우터 루트에서 상속(`@`), `$` 변수, 참조를 모두 풀고 컨트롤 이름과 정의 이름을 버린 트리다. 이름만 다르고 속성이 같으면 같다고 본다. 차이는 0이고(허용 목록이 비어 있다), 렌더에 영향을 주는 속성 하나만 바꿔도 비교기가 차이를 잡는지도 대조군으로 확인한다. 서버 쪽도 같이 비교한다. `openScreen`이 보내는 폼의 제목과 버튼 2022개(글자, 아이콘, 순서)가 원본과 같고, 페이지 버튼과 진행 버튼의 응답 처리도 같다.

## 통합 애드온에서 실행 방법

상단 오른쪽 "통합 테스트 애드온 다운로드"로 받은 애드온에서 막대기를 써서 예시 고르기 창에서 고르거나, 명령을 실행한다. 게임 안 글자는 영어이며, 고르기 창(`json-ui-react Examples`)의 메뉴 라벨은 `Research screen`이다. 항목을 고르기 전 상세 자리에는 `Pick a research.`가 보인다.

버튼 2022개, 폼 제목 `jur:re`.

```text
/scriptevent jur:open research
```
