# 컴포넌트 직접 만들기

고수준 컴포넌트는 저수준 API(`render`, `createSlots`, `createPack`, 요소의 `collection_index`와 `$` 변수)를 조립한 함수일 뿐이다. 필요한 부품이 없으면 같은 방법으로 직접 만든다. 이 페이지는 고수준 컴포넌트 `IconRow`(머리글 + 아이콘 칸 한 줄)를 예로 들어 단계별로 따라간다. 소스는 빌드할 때 `src/high/record.tsx`에서 읽은 그대로다.

:::note 어디서 만드나
이 페이지의 `IconRow`는 라이브러리 안(`src/high`)의 부품이라서 화면 문맥 도우미(`useScreen`, `useRecord`, `ref`, `GEOM`)를 쓴다. 이 도우미는 `json-ui-react` 루트로 내보내지 않는다. 앱에서 같은 모양의 부품을 만들 때는 아래 [도우미 없이 만들기](#standalone)처럼 공개 API(`createSlots`, `createPack`, `render`)만 쓴다. 이미 있는 부품을 쌓기만 하면 되는 경우(예: 연구 화면의 `ItemDetail`)는 [연구 화면](./research.mdx)을 본다.
:::

## 만들 것

상세 판 안에서 머리글 한 줄과 아이콘 칸이 가로로 늘어선 줄이다. 누를 수는 없고 칸마다 아이콘과 오른쪽 아래 숫자만 보인다.

```tsx
<IconRow name="mats" label="Required materials" count={8} />
```

## 1단계: props와 서버 데이터 모양을 정한다

- `name`은 레코드 키다. 서버는 `mats: [[아이콘, 개수], ...]`를 보낸다.
- `label`은 줄 위의 정적 머리글, `count`는 칸 수(최대), `badge`는 개수 없이 아이콘만 준 칸에 보일 글자다.

<Source data={[source[0]]} />

## 2단계: 무엇으로 낮출지 정한다

JSON UI에서 줄은 이렇게 된다. 머리글은 `label`로, 칸은 `collection_name`을 가진 가로 `stack_panel`의 직속 자식이다. 칸마다 고정 `collection_index`를 받아야 칸마다 다른 버튼의 데이터를 읽는다(COL-38, COL-50). 칸 모양은 테마가 이미 정의한 `icon_slot`을 참조한다.

## 3단계: 버튼 번호를 받는다

칸마다 서버 버튼 하나가 필요하다. 저수준에서는 `createSlots()`로 번호를 받는다. `slots.range(name, count)`는 연속 번호 구간을, `slots.blocks(name, count, fields)`는 칸 하나(레코드 하나)마다 같은 필드 목록을 가진 블록을 만든다. `.at(i)`, `.at(index, field)`가 번호를 돌려준다.

`IconRow`는 이를 직접 부르지 않는다. 상세 안에서는 `useRecord().field(...)`가 필드를 밝히고(`{ field, kind: "icon", key, index }`) 그 칸 블록 안의 번호를 돌려준다. 격자(`SelectGrid`)가 `blocks`를 만들고 칸마다 필드 목록을 모은다. 이 필드 설명(`FieldSpec`)을 생성 서버 모듈도 읽으므로 서버가 보내는 버튼과 화면의 번호가 어긋나지 않는다.

## 4단계: 요소를 쓴다

저수준에서는 요소가 JSON UI 컨트롤 그대로다. `<stack_panel>`, `<use def=...>`처럼 소문자 태그를 쓰고 JSON UI 속성(`size`, `collection_index`, `collection_name`)을 그대로 준다. `<use>`는 이름 있는 정의를 `이름@정의`로 참조한다. 정의 이름은 `ref(ctx, "icon_slot")`이 화면의 네임스페이스를 붙여 돌려준다.

<Source data={[source[1]]} />

코드를 순서대로 읽으면 이렇다.

1. `useScreen`, `useRecord`로 화면 문맥과 현재 칸의 레코드를 받는다. 상세 밖에서 쓰면 오류를 던진다.
2. `count`를 검사한다. 상세 폭에 들어가지 않으면 빌드할 때 알아듣기 쉬운 오류를 낸다.
3. `slots`: 칸마다 `rec.field(...)`로 번호를 받는다.
4. 머리글(`<use ... def=header_label text=...>`)과 칸 줄(`<stack_panel ...>`)을 돌려준다. 조각(`<>...</>`)이라 두 요소가 형제로 놓인다.

## 5단계: 낮춘 결과를 본다

`render`가 요소를 컨트롤 트리로, `toBody`가 JSON 본문으로 바꾼다. 위 `IconRow`가 연구 화면의 칸 0 상세에서 낮춰진 결과는 아래와 같다(prebuild가 `rp/ui/jur.json`에서 뽑는다). 칸마다 `collection_index`가 연속 번호(여기서는 105부터)다.

칸 정의(`jur.icon_slot`)는 서버가 빈 칸 표식(`§0§e§r`)을 보내면 칸을 숨긴다. 그래서 데이터가 모자란 칸은 자리를 차지하지 않고 있는 칸만 왼쪽부터 붙는다(LAY-04).

## 6단계: 쓰고 서버에서 연다

만든 부품은 다른 고수준 부품처럼 쓴다. 서버는 레코드 키와 같은 이름으로 데이터를 보낸다.

```tsx
<DetailPanel>
  <IconRow name="mats" label="Required materials" count={8} />
</DetailPanel>
```

```js
openScreen(player, "research", {
  needed: [{ icon: "textures/items/book_normal", mats: [["textures/items/coal", 3]] }],
});
```

## 도우미 없이 만들기 {#standalone}

앱 코드에서는 공개 API만으로 같은 일을 한다. 번호는 `createSlots`, 정의는 `createPack`, 요소는 직접 쓴다.

```tsx
import { createPack, createSlots } from "json-ui-react";

const slots = createSlots();
const mats = slots.range("mats", 4); // 버튼 번호 4개(0..3)

const pack = createPack();
const ns = pack.ns("my", "my.json");

// 칸 정의
ns.define("slot", <panel name="slot" size={[18, 18]} />);

// 칸 4개 줄: 부모는 collection_name을 가진 가로 stack_panel, 칸은 직속 자식(COL-38, COL-50)
const MatsRow = () => (
  <stack_panel name="mats" orientation="horizontal" size={["100%", 18]} collection_name="form_buttons">
    {Array.from({ length: 4 }, (_, j) => (
      <use name={`s${j}`} def="my.slot" collection_index={mats.at(j)} />
    ))}
  </stack_panel>
);
ns.define("mats_row", <MatsRow />);

pack.files();    // { "ui/my.json": ..., "ui/_ui_defs.json": ... }
slots.layout();  // { total: 4, ranges: [{ name: "mats", start: 0, count: 4 }], blocks: [] }
```

`slots.layout()`은 서버가 번호를 맞추는 데 쓴다. `serverModule(layout)`(`json-ui-react`)로 `decode`가 든 서버 모듈을 만들 수 있다. 자세한 API는 [API 레퍼런스의 저수준 부](../reference/low-level.mdx)에 있다.
