# 규칙 API (getRule, listRules, diag)

`json-ui-react`는 bedrock-research의 JSON UI 규칙 전부를 코드에서 조회할 수 있게 낸다. 규칙마다 ID, 한국어와 영어 문장, 근거, 출처, 위키 링크, 그리고 **강제 단계**가 붙는다.

## 강제 단계

| 단계 | 뜻 |
| --- | --- |
| `type` | TypeScript가 컴파일 때 거절한다 |
| `rewrite` | 빌드가 고쳐 쓰고 info로 알린다 |
| `forbid` | 빌드가 error나 warn으로 알린다 |
| `doc` | 검사할 수 없다. 문장과 링크만 둔다 |

각 규칙은 `status`도 가진다. 이 저장소의 코드가 실제로 검사하면 `enforced`, 아직 아니면 `planned`다.

## 단계별 개수

| 단계 | 규칙 수 | enforced | planned |
| --- | ---: | ---: | ---: |
| `type` | 37 | 14 | 23 |
| `rewrite` | 8 | 8 | 0 |
| `forbid` | 72 | 66 | 6 |
| `doc` | 329 | 0 | 329 |
| 합계 | 446 | 88 | 358 |

이 표는 문서를 쓸 때 `listRules`로 센 값이다. 코드가 바뀌면 `listRules({ stage, status }).length`로 다시 센다.

## 사용

```ts
import { getRule, listRules, ruleUrl, diag, RULE_IDS, STAGES } from "json-ui-react";

const r = getRule("INP-10");
r.title.ko;   // 규칙 문장
r.stage;      // "type" | "rewrite" | "forbid" | "doc"
r.url;        // 위키 링크(ko), r.urlEn은 영어

ruleUrl("COL-01", "en");                       // 영어 위키 링크
listRules({ category: "COL", stage: "type" }); // 필터 조회
listRules({ status: "enforced" });             // 실제로 검사하는 규칙

// 빌드 진단 만들기: 메시지를 생략하면 규칙 문장이 들어간다.
const d = diag("BND-05", "error", "controls.0.bindings.1");
d.url; // 위키 링크가 함께 붙는다
```

- `RULE_IDS`는 정렬된 전체 ID, `RULE_INFO`는 ID별 원본 정보, `STAGES`는 단계표다.
- `RuleId`는 모든 ID의 리터럴 유니온이라 오타는 컴파일 때 걸린다.
- 단계표에 없는 규칙은 `{ stage: "doc", status: "planned" }`로 본다.

## 검사 엔진 (runChecks, ALL_CHECKS)

`forbid`와 `rewrite` 규칙은 `src/check/`의 검사로 구현된다. `runChecks`는 생성된 파일 묶음을 돌며 검사마다 진단을 모은다. 진단은 경로, 규칙 순으로 정렬되고 `url`이 붙는다. 고수준과 엔티티 빌드는 `ALL_CHECKS`를 자동으로 돌린다.

```ts
import { runChecks, ALL_CHECKS } from "json-ui-react";

const { diagnostics } = runChecks(files, ALL_CHECKS);
// rewrite 검사는 { rewrite: true }일 때만 돌고, 깊은 복사본을 고쳐 새 files로 돌려준다.
const fixed = runChecks(files, ALL_CHECKS, { rewrite: true, only: ["HOST-34"] });
fixed.files; // 고친 사본(입력은 그대로)
```

`only`로 규칙을 좁힐 수 있다. 라우터 루트를 알면 `allChecks(routedRoots)`로 검사 목록을 만든다.

## 배치 질의와 해결기 (explainPlacement, solvePlacement)

`CAPABILITIES`는 컨트롤 타입별로 쓸 수 있는 속성을 담은 표다. `explainPlacement`는 부모 아래에 자식을 두면 어떤 규칙에 걸리는지 알려 주고, `solvePlacement`는 컨트롤 트리에서 그 문제를 고쳐 쓴다.

```ts
import { explainPlacement, solvePlacement } from "json-ui-react";

explainPlacement({
  parent: { type: "stack_panel", collection_name: "form" },
  child: { type: "image", props: { collection_index: 1 } },
});
// { ok: false, problems: [{ rule: "COL-02", level: "error", fix: "move-index", message }] }

const { nodes, diagnostics } = solvePlacement(tree, { strict: true });
// 고친 새 트리와 info 진단. 못 고친 error는 strict: false면 warn으로 낮춘다.
```
