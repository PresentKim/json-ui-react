# Rules API (getRule, listRules, diag)

`json-ui-react` exposes every bedrock-research JSON UI rule in code. Each rule carries an ID, Korean and English text, evidence, sources, a wiki link and an **enforcement stage**.

## Enforcement stages

| Stage | Meaning |
| --- | --- |
| `type` | TypeScript rejects it at compile time |
| `rewrite` | The build fixes it and reports info |
| `forbid` | The build reports an error or warning |
| `doc` | Cannot be checked; text and link only |

Each rule also has a `status`: `enforced` when code in this repo really checks it, otherwise `planned`.

## Counts per stage

| Stage | Rules | enforced | planned |
| --- | ---: | ---: | ---: |
| `type` | 37 | 14 | 23 |
| `rewrite` | 8 | 8 | 0 |
| `forbid` | 72 | 66 | 6 |
| `doc` | 329 | 0 | 329 |
| Total | 446 | 88 | 358 |

The table was counted with `listRules` when this page was written. Recount with `listRules({ stage, status }).length` after code changes.

## Usage

```ts
import { getRule, listRules, ruleUrl, diag, RULE_IDS, STAGES } from "json-ui-react";

const r = getRule("INP-10");
r.title.en;   // rule text
r.stage;      // "type" | "rewrite" | "forbid" | "doc"
r.url;        // wiki link (ko); r.urlEn is the English one

ruleUrl("COL-01", "en");                       // English wiki link
listRules({ category: "COL", stage: "type" }); // filtered lookup
listRules({ status: "enforced" });             // rules that are really checked

// Build a diagnostic: the message defaults to the rule text.
const d = diag("BND-05", "error", "controls.0.bindings.1");
d.url; // the wiki link comes along
```

- `RULE_IDS` is the sorted list of IDs, `RULE_INFO` the raw info per ID, `STAGES` the stage table.
- `RuleId` is a literal union of all IDs, so typos fail at compile time.
- A rule missing from the stage table counts as `{ stage: "doc", status: "planned" }`.

## Check engine (runChecks, ALL_CHECKS)

`forbid` and `rewrite` rules are implemented as checks in `src/check/`. `runChecks` walks a set of generated files and collects each check's diagnostics, sorted by path then rule, with `url` attached. The high-level and entity builds run `ALL_CHECKS` automatically.

```ts
import { runChecks, ALL_CHECKS } from "json-ui-react";

const { diagnostics } = runChecks(files, ALL_CHECKS);
// Rewrite checks run only with { rewrite: true } and fix a deep copy, returned as new files.
const fixed = runChecks(files, ALL_CHECKS, { rewrite: true, only: ["HOST-34"] });
fixed.files; // the fixed copy (the input is untouched)
```

`only` narrows the rules. When you know the router roots, build the check list with `allChecks(routedRoots)`.

## Placement query and solver (explainPlacement, solvePlacement)

`CAPABILITIES` is a table of the props each control type accepts. `explainPlacement` tells which rules a child under a parent would hit, and `solvePlacement` fixes those problems in a control tree.

```ts
import { explainPlacement, solvePlacement } from "json-ui-react";

explainPlacement({
  parent: { type: "stack_panel", collection_name: "form" },
  child: { type: "image", props: { collection_index: 1 } },
});
// { ok: false, problems: [{ rule: "COL-02", level: "error", fix: "move-index", message }] }

const { nodes, diagnostics } = solvePlacement(tree, { strict: true });
// A fixed new tree plus info diagnostics. Unfixable errors become warn with strict: false.
```
