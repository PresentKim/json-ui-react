# json-ui-react


Compile server-form screens written in TSX into **static JSON UI** and a **server module for the behavior pack**. You write a screen with high-level components such as `<Screen>`, `<ButtonList>` and `<Tabs>`, and open it from the server with a single call to the generated `openScreen(player, id, data)`. It has zero runtime dependencies, and the same input always produces byte-identical output.

```tsx
import { Screen, ButtonList } from "json-ui-react";

export default (
  <Screen id="router" title="Router: screen picked by title prefix">
    <ButtonList name="buttons" count={4} />
  </Screen>
);
```

```js
import { openScreen } from "./generated/screens.js";

openScreen(player, "router", {
  buttons: [["Apple", "textures/items/apple"], ["Bread", "textures/items/bread"]],
}).then((hit) => {
  // null (canceled) | { name: "buttons", index: 0..3 }
});
```

## Why compile at build time

Bedrock JSON UI has no JS runtime, so a screen's structure is baked statically into the resource pack. Wiring up a router, radio tabs, fixed `collection_index` cells and the button index layout (`102 + 20k + 19`) by hand makes it easy for the JSON and the server code to drift apart. Generating both in a single build step means they cannot disagree.

## Pipeline

| Stage | What it does |
| --- | --- |
| TSX screen | Write the screen with `<Screen>` and the other high-level components |
| `buildScreens` | Builds the screens into one pack: the theme, a single router, the `server_form` hook and the generated server module |
| Low-level layer | The built-in JSX runtime, `render`, `createPack` and `createSlots` lower everything into JSON UI controls |
| Lint | Checks the generated JSON and reports diagnostics tagged with rule IDs |
| Behavior pack | The generated `openScreen` sends the form with its buttons in the right order and decodes the response into `{ name, index }` |

When a part you need is missing, you can build it directly with the low-level API. [Building your own component](../components/custom-component.mdx) shows how, and [part 3 of the API reference](../reference/low-level.mdx) covers the low-level API. The [research screen](../components/research.mdx) is a large example assembled only from high-level parts.

## Built on the bedrock-research wiki

json-ui-react is built on the JSON UI rules (rule IDs) and in-game measurements of the [bedrock-research](https://github.com/PresentKim/bedrock-research) repository (the Bedrock development wiki). The JSON UI techniques the components lower to (a single router, radio tabs, fixed `collection_index` cells, grid lists) and the rule IDs in these docs and in lint diagnostics (such as `COL-50`) use the same IDs as the JSON UI chapters of that wiki. The [research screen](../components/research.mdx) example reproduces the measured screen (FFR) described on the wiki's [server form research screen page](https://github.com/PresentKim/bedrock-research/blob/main/docs/design/server-form-research-screen.mdx).

The prefix of a rule ID tells you which wiki chapter to open: `COL-*` is collections and factories, `INP-*` is input, buttons and toggles, `BND-*` is bindings and `EXP-*` is expressions and operators. The full table is on the [start page](../index.mdx#rule-ids).
